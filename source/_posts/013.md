# Qt 实战：从零搭建一个工业水泵监控 HMI

> Modbus TCP + 实时图表 + 报警日志 + 可独立部署 —— 一篇带你走完上位机的全部基础流程

## 引子：先看效果再决定要不要看

这是一个 **水泵监控上位机**。它要做的事情很简单：

- 通过 **Modbus TCP** 协议，每秒去读一次下位机（PLC 或模拟器）的压力、温度、水泵状态
- 把压力画成一条**实时滚动曲线**
- 压力超过阈值就**弹窗报警**，并把记录写进 SQLite 数据库
- 一个按钮可以**远程启停水泵**

跑起来大概是这样的（贴一张你自己截的运行截图）：

![PumpHMI 运行截图](图位置占位)

技术栈：**Qt 6.11 + MinGW 64-bit + QtCharts + QtSerialBus + QtSql**。
代码量：两个 cpp / h 文件，不到 350 行。

这篇文章会从**空白工程**开始，一步一步把它做完。中途我会把自己踩过的几个**反直觉的坑**单独点出来 —— 因为说实话，这类小项目的难点不在 Qt 本身，而在"我以为是 bug、其实是设计如此"的瞬间。

## 第 1 章 · 环境准备

### 1.1 Qt 安装与模块

去 [qt.io](https://www.qt.io/download-qt-installer) 下 Qt Online Installer，登录账号（个人免费），选 **Qt 6.11.x**，编译器选 **MinGW 64-bit**。

**必须勾选的模块**（默认有些不装）：

- ✅ Qt Charts（实时曲线用）
- ✅ Qt Serial Bus（Modbus 在这个模块下）
- Qt Sql、Qt Widgets 是核心模块，自动安装

装完之后 Qt 大概在这种路径下：

```
D:\App\Qt6.11\6.11.1\mingw_64\
```

记住这个路径，第 11 章部署时还要用。

### 1.2 安装一个 Modbus Slave 模拟器

HMI 是"上位机"，它必须有个"下位机"才能通信。真实场景里下位机是 PLC，开发时我们用模拟器代替。Windows 上推荐 **Witte Software** 的 **Modbus Slave**（30 天试用，足够学习）：

下载地址：[modbustools.com](https://www.modbustools.com/modbus_slave.html)

装好后**用管理员身份运行**（因为 502 端口在 Windows 上需要管理员权限，这是头号大坑）。配置：

| 项         | 值                    |
| ---------- | --------------------- |
| Connection | Modbus TCP/IP         |
| Port       | 502                   |
| Slave ID   | 1                     |
| Function   | 03 Holding Register   |
| Address    | 0                     |
| Quantity   | 3（覆盖地址 0、1、2） |

主窗口会显示三个寄存器的当前值，**双击任何一个数字可以手动编辑** —— 这是我们后面调试时主要的操作。

## 第 2 章 · CMake 项目骨架

用 Qt Creator 新建 "Qt Widgets Application"，它会自动生成 `CMakeLists.txt`、`main.cpp`、`mainwindow.{h,cpp}`、`mainwindow.ui`。

**第一件事：把 `mainwindow.ui` 删掉**。我们这个项目用纯代码搭界面，不用 Designer，省得 UI 文件和代码不同步互相打架。

### 2.1 CMakeLists.txt 关键行解读

修改 `CMakeLists.txt`，让它知道我们要用哪些 Qt 模块：

```cmake

find_package(Qt${QT_VERSION_MAJOR} REQUIRED COMPONENTS Widgets SerialBus Charts Sql)

set(PROJECT_SOURCES
    main.cpp
    mainwindow.cpp
    mainwindow.h
)

target_link_libraries(PumpHMI PRIVATE
    Qt${QT_VERSION_MAJOR}::Widgets
    Qt${QT_VERSION_MAJOR}::SerialBus
    Qt${QT_VERSION_MAJOR}::Charts
    Qt${QT_VERSION_MAJOR}::Sql
```

#### 🟡 坑点 1：QtCharts 在 Qt5 / Qt6 的命名空间差异

Qt5 里 `QChart`、`QLineSeries` 等类都在 `QtCharts` 命名空间下，不写 `using namespace QtCharts` 头文件直接编译报"不存在的类型"。Qt6 把它移到了全局命名空间。

Qt 官方给了一个宏 `QT_CHARTS_USE_NAMESPACE` —— **Qt5 下展开为 `using namespace QtCharts;`，Qt6 下展开为空**。加上这一行，两边都能编。

## 第 4 章 · Modbus TCP 通信

终于到正菜了。

### 4.1 寄存器地址约定

这是上位机和下位机之间的**协议**，必须先定下来：

| 地址 | 含义     | 编码方式                         |
| ---- | -------- | -------------------------------- |
| 0    | 压力     | 实际值 × 100（写整数避免传浮点） |
| 1    | 温度     | 实际值 × 10                      |
| 2    | 水泵状态 | 0 = 停止，1 = 运行               |

为什么不直接传浮点？因为标准 Modbus 寄存器是 **16 位整数**。传浮点需要把 32 位 float 拆成两个寄存器，编解码麻烦。工业上常见做法就是**用整数倍率约定**，简单可靠。

### 4.2 连接：QModbusTcpClient 三件套

```cpp
void MainWindow::connectModbus()
{
    m_modbusClient = new QModbusTcpClient(this);

    m_modbusClient->setConnectionParameter(
        QModbusDevice::NetworkPortParameter, 502);
    m_modbusClient->setConnectionParameter(
        QModbusDevice::NetworkAddressParameter, "127.0.0.1");
    m_modbusClient->setTimeout(1000);
    m_modbusClient->setNumberOfRetries(3);

    if (!m_modbusClient->connectDevice()) {
        statusBar()->showMessage(
            QString("连接下位机失败: %1").arg(m_modbusClient->errorString()));
        m_pumpButton->setEnabled(false);
        m_pumpButton->setText("未连接下位机");
        return;
    }

    statusBar()->showMessage("已连接到下位机 (127.0.0.1:502)", 3000);
    m_pumpButton->setEnabled(true);

    m_pollTimer = new QTimer(this);
    connect(m_pollTimer, &QTimer::timeout, this, &MainWindow::readPressure);

    resetDisplay();
}
```

#### 🟡 坑点 2：永远要给用户可见的失败反馈

最早我写的版本，连接失败时只 `statusBar()->showMessage(..., 3000)` —— 状态栏闪 3 秒后消失。结果调试时 Modbus Slave 没开，启动 HMI 后**啥反应都没有**，按"启动水泵"也没反应（因为 `togglePump` 第一行守卫语句直接 return）。

最后是我盯着代码看了五分钟才反应过来 —— 是连接失败了，按钮里的 Modbus 命令根本发不出去。

后来改成两件事一起做：

1. 状态栏**常驻**显示失败原因（不加超时参数）
2. 把按钮**直接禁用**，文字改成"未连接下位机"

这样一启动就能看出来"哦原来是模拟器没开"。

**写工控软件，宁可弹窗扰民也别静默失败。**

### 4.3 定时读取与异步回调

Modbus 客户端的读写都是**异步**的，请求发出去后立刻返回一个 `QModbusReply`，等数据到了再触发 `finished()` 信号。

```cpp
void MainWindow::readPressure()
{
    if (!m_modbusClient ||
        m_modbusClient->state() != QModbusDevice::ConnectedState)
        return;

    QModbusDataUnit readUnit(
        QModbusDataUnit::HoldingRegisters,  // 寄存器类型
        0,                                   // 起始地址
        3                                    // 读取数量
        );

    if (auto *reply = m_modbusClient->sendReadRequest(readUnit, 1)) {
        if (!reply->isFinished()) {
            connect(reply, &QModbusReply::finished,
                    this, &MainWindow::onReadReady);
        } else {
            delete reply;  // 广播请求或同步错误，直接删
        }
    }
}

void MainWindow::onReadReady()
{
    auto *reply = qobject_cast<QModbusReply *>(sender());
    if (!reply) return;

    if (reply->error() == QModbusDevice::NoError) {
        const QModbusDataUnit unit = reply->result();

        float pressure = unit.value(0) / 100.0f;
        float temperature = unit.value(1) / 10.0f;

        m_pressureLabel->setText(
            QString("%1 MPa").arg(pressure, 0, 'f', 2));
        m_temperatureLabel->setText(
            QString("%1 °C").arg(temperature, 0, 'f', 1));

        if (pressure > m_alarmThreshold) {
            triggerAlarm(pressure);
        } else if (m_alarmActive) {
            m_alarmActive = false;
            applyNormalStyle();
        }

        updateChart(pressure);

    } else {
        statusBar()->showMessage(
            QString("读取失败: %1").arg(reply->errorString()), 2000);
    }

    reply->deleteLater();
}
```

几个关键点：

1. **`sendReadRequest(readUnit, 1)` 第二个参数是 Slave ID**，不是寄存器地址。新手很容易混淆。
2. **`reply->deleteLater()` 不能漏**，否则会内存泄漏。
3. **回调里要先判断 `reply->error()`**，不然 `result()` 拿到的可能是垃圾数据。

定时器在第 9 章会改成"按钮控制启停"，这里先不 start。

## 第 5 章 · 实时压力曲线

### 5.1 QtCharts 基础三件套

```cpp
void MainWindow::setupChart()
{
    m_series = new QLineSeries();
    m_series->setName("压力 (MPa)");
    m_series->setPen(QPen(QColor("#2196F3"), 2));

    m_chart = new QChart();
    m_chart->addSeries(m_series);
    m_chart->setTitle("实时压力趋势");
    m_chart->setAnimationOptions(QChart::NoAnimation);  // 实时数据不要动画

    m_axisX = new QDateTimeAxis();
    m_axisX->setFormat("HH:mm:ss");
    m_axisX->setTitleText("时间");
    m_chart->addAxis(m_axisX, Qt::AlignBottom);
    m_series->attachAxis(m_axisX);

    m_axisY = new QValueAxis();
    m_axisY->setRange(0, 3.0);
    m_axisY->setTitleText("压力 (MPa)");
    m_axisY->setLabelFormat("%.1f");
    m_chart->addAxis(m_axisY, Qt::AlignLeft);
    m_series->attachAxis(m_axisY);

    QChartView *chartView = new QChartView(m_chart);
    chartView->setRenderHint(QPainter::Antialiasing);

    centralLayout->addWidget(chartView, 1);
}
```

注意 **`QChart::NoAnimation`** —— 默认 QtCharts 给每次数据变化加缓动动画，实时图表里这是灾难：新数据一来就开始 0.5 秒的"平滑过渡"，曲线看起来一直在抖。**实时数据必须关掉动画**。

### 5.2 滑动窗口：只显示最近 60 秒

```cpp
void MainWindow::updateChart(float pressure)
{
    QDateTime now = QDateTime::currentDateTime();

    m_series->append(now.toMSecsSinceEpoch(), pressure);

    QDateTime cutoff = now.addSecs(-60);
    while (m_series->count() > 0 &&
           m_series->at(0).x() < cutoff.toMSecsSinceEpoch()) {
        m_series->remove(0);
    }

    m_axisX->setRange(cutoff, now);
}
```

每秒一个点，60 秒最多 60 个点。**为什么要主动删旧点？** —— 如果不删，跑一天就有 86400 个点，内存和绘制都会越来越慢。工业 HMI 里"看最近一分钟趋势"是很合理的需求，更长的历史用另一个对话框 + 数据库分页查看就行。

## 第 6 章 · 报警系统

### 6.1 报警三件事：弹窗、变红、记日志

```cpp
void MainWindow::triggerAlarm(float pressure)
{
    m_pressureLabel->setStyleSheet(
        "color: white; background-color: #F44336;"
        "font-size: 32px; padding: 10px; border-radius: 8px;");

    m_statusLight->setStyleSheet(
        "background-color: #F44336; border-radius: 12px;"
        "min-width: 24px; min-height: 24px;");

    if (!m_alarmActive) {
        m_alarmActive = true;
        QMessageBox::warning(this, "压力报警",
            QString("当前压力 %1 MPa 超过阈值 %2 MPa！\n请立即检查水泵运行状态。")
                .arg(pressure, 0, 'f', 2)
                .arg(m_alarmThreshold, 0, 'f', 2));
    }

    logAlarm(pressure,
        QString("压力超阈值: %1 MPa > %2 MPa")
            .arg(pressure, 0, 'f', 2)
            .arg(m_alarmThreshold, 0, 'f', 2));
}
```

#### 🟡 坑点 3：用 `m_alarmActive` 防止反复弹窗

如果不加这个 flag，**每秒读一次** → 每秒都超阈值 → 每秒弹一个对话框，根本关不完。

`m_alarmActive` 充当一个**边沿检测**：只在"正常 → 报警"的瞬间弹一次。回落到阈值以下时，在 `onReadReady` 里清零它，下次再超阈值才会再弹。

**最初版本我用的是函数内 `static bool`**，结果发现状态没法外部清理。后来挪成成员变量 `m_alarmActive`，配合 `applyNormalStyle()` 在恢复正常时统一处理，逻辑清晰多了。

### 6.2 恢复正常的样式联动

```cpp
void MainWindow::applyNormalStyle()
{
    m_pressureLabel->setStyleSheet(
        "color: #2196F3; font-size: 32px; padding: 10px;");
    m_temperatureLabel->setStyleSheet(
        "color: #FF9800; font-size: 20px; padding: 10px;");
    m_statusLight->setStyleSheet(
        "background-color: #4CAF50; border-radius: 12px;"
        "min-width: 24px; min-height: 24px;");
}
```

`onReadReady` 里这样判断：

```cpp
if (pressure > m_alarmThreshold) {
    triggerAlarm(pressure);
} else if (m_alarmActive) {
    m_alarmActive = false;
    applyNormalStyle();
}
```

**只在"刚刚还在报警，现在恢复了"**的时刻调用 `applyNormalStyle`，避免每秒都瞎刷一遍样式表（虽然刷了也不会出错，但浪费）。

## 第 7 章 · 报警日志：SQLite + 表格

### 7.1 一次性初始化数据库

```cpp
void MainWindow::setupDatabase()
{
    m_db = QSqlDatabase::addDatabase("QSQLITE");
    m_db.setDatabaseName("pump_alarm_log.db");

    if (!m_db.open()) {
        qWarning() << "无法打开数据库:" << m_db.lastError().text();
        return;
    }

    QSqlQuery query;
    query.exec(
        "CREATE TABLE IF NOT EXISTS alarm_log ("
        "  id INTEGER PRIMARY KEY AUTOINCREMENT,"
        "  timestamp DATETIME DEFAULT CURRENT_TIMESTAMP,"
        "  pressure REAL,"
        "  message TEXT"
        ")"
    );
}
```

`pump_alarm_log.db` 文件默认会出现在**当前工作目录**（在 Qt Creator 里运行时，就是 build 目录里）。想放到固定位置可以用 `QStandardPaths::writableLocation` 指定。

### 7.2 写入一条报警

```cpp
void MainWindow::logAlarm(float pressure, const QString &message)
{
    QSqlQuery query;
    query.prepare(
        "INSERT INTO alarm_log (pressure, message) VALUES (?, ?)");
    query.addBindValue(pressure);
    query.addBindValue(message);
    query.exec();

    int row = m_logTable->rowCount();
    m_logTable->insertRow(row);
    m_logTable->setItem(row, 0,
        new QTableWidgetItem(
            QDateTime::currentDateTime().toString("yyyy-MM-dd HH:mm:ss")));
    m_logTable->setItem(row, 1,
        new QTableWidgetItem(QString::number(pressure, 'f', 2)));
    m_logTable->setItem(row, 2,
        new QTableWidgetItem(message));

    m_logTable->scrollToBottom();
}
```

#### 🟡 坑点 4：永远用参数化查询

千万别拼字符串 SQL：

```cpp
// ❌ 危险
query.exec("INSERT INTO alarm_log (message) VALUES ('" + message + "')");
```

只要 `message` 里有单引号或者奇怪字符，SQL 就被破坏了。哪怕 message 是程序内部生成的、不接受外部输入，养成 `prepare + addBindValue` 的习惯也好 —— **省得以后接入用户输入时给自己挖坑**。

## 第 8 章 · 水泵控制：写寄存器

### 8.1 togglePump：发一条写入请求

```cpp
void MainWindow::togglePump()
{
    if (!m_modbusClient ||
        m_modbusClient->state() != QModbusDevice::ConnectedState) {
        QMessageBox::warning(this, "未连接下位机",
            "Modbus 下位机未连接，无法控制水泵。\n"
            "请确认 127.0.0.1:502 上有 Modbus Slave 在运行。");
        return;
    }

    bool nextState = !m_pumpRunning;

    QModbusDataUnit writeUnit(
        QModbusDataUnit::HoldingRegisters, 2, 1);
    writeUnit.setValue(0, nextState ? 1 : 0);

    if (auto *reply = m_modbusClient->sendWriteRequest(writeUnit, 1)) {
        connect(reply, &QModbusReply::finished, this,
            [this, reply, nextState]() {
                if (reply->error() == QModbusDevice::NoError) {
                    m_pumpRunning = nextState;
                    m_pumpButton->setText(
                        m_pumpRunning ? "停止水泵" : "启动水泵");
                    m_pumpButton->setStyleSheet(m_pumpRunning
                        ? "background-color: #F44336; color: white; padding: 12px;"
                        : "background-color: #4CAF50; color: white; padding: 12px;");

                    if (m_pumpRunning) {
                        applyNormalStyle();
                        m_pollTimer->start(1000);
                        statusBar()->showMessage("水泵已启动，开始监测", 2000);
                    } else {
                        m_pollTimer->stop();
                        resetDisplay();
                        statusBar()->showMessage("水泵已停止，监测已暂停", 2000);
                    }
                } else {
                    statusBar()->showMessage(
                        QString("写入失败: %1").arg(reply->errorString()), 2000);
                }
                reply->deleteLater();
            });
    }
}
```

#### 🟡 坑点 5：写入失败时不要修改本地状态

我最初的写法是**先**把 `m_pumpRunning = !m_pumpRunning` 翻转，然后发请求。结果遇到网络抖动写入失败时，按钮文字已经改了、本地状态已经翻了，**实际下位机却没动**，HMI 和现场状态分裂。

改成现在这样：算出 `nextState`，发请求，**只有写入回调成功时才把 `nextState` 提交到 `m_pumpRunning`**。失败就维持原状 + 弹个错误提示。

这是**事务性思维** —— 写入操作要么整体成功要么整体回退，避免半成功的中间状态。

## 第 9 章 · 按需采集：停泵就清零

### 9.1 一个反直觉的设计决策

最初我的写法：连上 Modbus 就立刻 `m_pollTimer->start(1000)`，每秒轮询。**不管泵开没开**。

后来想了一下，对 demo / 学习场景，这样有个不太友好的现象：泵停了，但屏幕上数字还在跳、图表还在画线，因为模拟器里压力值是手动设的，不会因为"泵停了"就自动归零。**视觉上分裂**。

所以最后决定：**让"启停水泵"按钮同时充当"启停监测"的开关**。

| 状态          | 显示                      | 数据采集   |
| ------------- | ------------------------- | ---------- |
| 未启动 / 停机 | 全部 0、灰色              | 不读       |
| 运行中        | 实时数字 + 曲线，正常颜色 | 每秒读一次 |

### 9.2 resetDisplay：界面归零

```cpp
void MainWindow::resetDisplay()
{
    m_pressureLabel->setText("0.00 MPa");
    m_pressureLabel->setStyleSheet(
        "color: #9E9E9E; font-size: 32px; padding: 10px;");

    m_temperatureLabel->setText("0.0 °C");
    m_temperatureLabel->setStyleSheet(
        "color: #9E9E9E; font-size: 20px; padding: 10px;");

    m_statusLight->setStyleSheet(
        "background-color: #9E9E9E; border-radius: 12px;"
        "min-width: 24px; min-height: 24px;");

    if (m_series) {
        m_series->clear();
    }
    m_alarmActive = false;
}
```

在 `connectModbus()` 末尾、`togglePump` 的"停止"分支都调用它。

### 9.3 设计哲学：HMI 该不该一直监测？

我先把答案讲清楚：**真实工业 HMI 应该一直监测**，因为：

- 设备本地可能被人手动操作，HMI 不读就不知道
- 出故障的瞬间最值得记录
- HMI = 操作员的"眼睛"，眼睛不能闭

这个项目**故意违反了这个原则**，是为了演示更直观的视觉效果 —— 停泵后界面"安静下来"，看起来更符合用户直觉。

**做真实产品时，建议保留持续轮询，停泵后只是把数据显示成灰色或弱化样式，不要真停止采集。**

## 第 10 章 · 进阶：智能 Mock 让压力联动

### 10.1 模拟器是"白板"，不是"设备"

Modbus Slave 模拟器只是一块**白板**：寄存器 0 是 100、寄存器 2 是 0，三个数字之间**没有任何关系**。你点"停止水泵"，程序把寄存器 2 改成 0，但**寄存器 0 的压力还是 100**，因为模拟器不会做"泵停了所以压力降"的物理推演。

要看到漂亮的**泄压曲线**（停泵后压力指数衰减到 0），需要一个**会思考的模拟器**。30 行 Python 就够。

### 10.2 pymodbus 智能模拟脚本

```python
"""
PumpHMI 智能 Modbus Slave 模拟器
  寄存器 0: 压力 × 100
  寄存器 1: 温度 × 10
  寄存器 2: 水泵状态 (0/1)

物理逻辑：
  * 泵启动后：压力指数逼近 ~1.30 MPa，带 ±0.03 抖动
  * 泵停止后：压力指数衰减 → 0（泄压曲线）
  * 温度跟随泵状态：运行 → 35°C，停止 → 25°C
"""

import random, threading, time
from pymodbus.datastore import (
    ModbusSequentialDataBlock, ModbusServerContext, ModbusSlaveContext)
from pymodbus.server import StartTcpServer

TARGET_PRESSURE = 130   # 1.30 MPa
RISE_RATE       = 0.20
DECAY_RATE      = 0.85
PRESSURE_JITTER = 3
TEMP_RUN        = 350
TEMP_IDLE       = 250
TEMP_RATE       = 0.05
FC_HOLDING      = 3

store = ModbusSlaveContext(
    hr=ModbusSequentialDataBlock(0, [0, TEMP_IDLE, 0]))
context = ModbusServerContext(slaves={1: store}, single=False)

def simulate():
    while True:
        time.sleep(1)
        pressure = store.getValues(FC_HOLDING, 0, count=1)[0]
        temperature = store.getValues(FC_HOLDING, 1, count=1)[0]
        pump_on = store.getValues(FC_HOLDING, 2, count=1)[0] != 0

        if pump_on:
            new_p = pressure + (TARGET_PRESSURE - pressure) * RISE_RATE
            new_p += random.uniform(-PRESSURE_JITTER, PRESSURE_JITTER)
            new_p = max(0, int(new_p))
            new_t = int(temperature + (TEMP_RUN - temperature) * TEMP_RATE)
        else:
            new_p = int(pressure * DECAY_RATE)
            new_t = int(temperature + (TEMP_IDLE - temperature) * TEMP_RATE)

        store.setValues(FC_HOLDING, 0, [new_p])
        store.setValues(FC_HOLDING, 1, [new_t])

if __name__ == "__main__":
    threading.Thread(target=simulate, daemon=True).start()
    print(">>> Mock Modbus Slave on 127.0.0.1:502 (Unit ID = 1)")
    StartTcpServer(context=context, address=("127.0.0.1", 502))
```

使用方法：

1. 关闭 Witte Modbus Slave（502 端口要让出来）
2. `pip install pymodbus`
3. **以管理员身份**运行：`python mock_slave.py`
4. 启动 PumpHMI，点"启动水泵"

效果：压力会**几秒内升到 1.30 MPa 左右并轻微抖动**，停泵后**画出一条平滑的指数衰减曲线**。

### 10.3 测试报警

把 `TARGET_PRESSURE` 改成 `160`，泵启动后压力会冲过 1.50 MPa，触发弹窗 + 数据库写入 + 表格新增一行 —— **一次性把整个报警链路都测了**。

## 第 11 章 · 部署：脱离 Qt 安装独立运行

写完之后，想把 exe 拷到没装 Qt 的电脑上跑？双击会报"缺少 Qt6Core.dll" —— Qt 的 DLL 没拷过去。

**解决方法：用 `windeployqt` 一键扫描依赖**。

### 11.1 先切到 Release 构建

Qt Creator 左下角点 Kit 选择器 → Build 那栏选 **Release** → `Ctrl+B`。

输出目录大概是：

```
E:\QtTest\Project3\PumpHMI\build\Desktop_Qt_6_11_1_MinGW_64_bit-Release\
```

里面有 `PumpHMI.exe`。直接双击会闪退（缺 dll）。

### 11.2 跑 windeployqt

打开普通 cmd（`Win+R` → `cmd`），两行命令：

```bat
cd /d E:\QtTest\Project3\PumpHMI\build\Desktop_Qt_6_11_1_MinGW_64_bit-Release
"D:\App\Qt6.11\6.11.1\mingw_64\bin\windeployqt.exe" PumpHMI.exe
```

> 把 `D:\App\Qt6.11\6.11.1` 换成你自己的 Qt 安装路径。

它会自动扫描 exe 的依赖，拷过来：

- Qt 模块 DLL：`Qt6Core.dll`、`Qt6Widgets.dll`、`Qt6Charts.dll`、`Qt6SerialBus.dll`、`Qt6Sql.dll` ...
- MinGW 运行时：`libgcc_s_seh-1.dll`、`libstdc++-6.dll`、`libwinpthread-1.dll`
- 平台插件：`platforms\qwindows.dll`（缺这个 Qt 程序在 Windows 上直接闪退）
- SQL 驱动：`sqldrivers\qsqlite.dll`
- TLS / 图像格式 / 翻译文件等

跑完之后，Release 目录就**可以独立运行**了，双击 exe 试一下。

#### 🟡 坑点 6：MSYS2 和 Qt 官方的 windeployqt 不能混用

如果你电脑上还装了 MSYS2，`where windeployqt` 可能会找到：

```
C:\msys64\mingw64\bin\windeployqt.exe   ← MSYS2 自己的
```

这个**不能用**！MSYS2 装的 Qt 版本和你 Qt 官方安装包的版本基本对不上，部署后会出现 "DLL 入口点找不到" 之类的诡异错误。

**始终用全路径调用 Qt 官方的那个**：

```bat
"D:\App\Qt6.11\6.11.1\mingw_64\bin\windeployqt.exe" PumpHMI.exe
```

### 11.3 哪些文件可以删

部署完后 Release 目录里有些是**构建副产物**，发给别人时可以删：

## 第 12 章 · 那些我以为是 bug 的瞬间

写代码的过程里，**真正的难题不是 Qt 的 API**，而是一连串"我以为程序坏了，结果是我没想清楚"的瞬间。这一章把我开发过程中真实问过的问题原样列出来 —— 因为我相信，**你也会问同样的问题**。

### 💬 "为什么启动没有反应"

我点了"启动水泵"按钮 —— **没反应**。

第一反应：按钮坏了？信号槽没连上？

排查后才发现：点击信号确实到了 `togglePump()`，但**函数第一行**：

```cpp
if (!m_modbusClient ||
    m_modbusClient->state() != QModbusDevice::ConnectedState)
    return;
```

直接 return 了。原因是 **Modbus 模拟器根本没启动**，502 端口没人监听，`connectDevice()` 在程序启动时就失败了。状态栏闪过一行"连接下位机失败"3 秒后消失，我根本没注意到。

**教训**：失败要让用户**看得见、关不掉**。后来我把失败提示改成状态栏常驻 + 按钮直接禁用 + 文字改"未连接下位机"，三重提示才算合格。

### 💬 "为什么只显示压力，其他数据没有，是不用显示吗"

我看到代码里明明读了三个寄存器，但界面**只有压力数字**。

```cpp
float pressure = unit.value(0) / 100.0f;    // ✓ 显示了
float temperature = unit.value(1) / 10.0f;  // 读了
Q_UNUSED(temperature);                       // ← 直接扔掉
int pumpStatus = unit.value(2);              // 只用于同步按钮
```

**读了数据 ≠ 显示了数据**。如果对应的 UI 控件没创建，数据就成了内存里的孤儿。后来加了一个 `m_temperatureLabel`，在顶部行插进去，温度才出现在界面上。

**教训**：读、用、显示是**三件独立的事**。看到 `Q_UNUSED` 就要警觉 —— 这个变量是不是应该被用上？

### 💬 "Modbus Slave 里面那个 2 的值是 0 还是 1 有什么区别"

这个问题问出来我才意识到：**Modbus 寄存器值的含义完全是协议层的约定**，不是 Modbus 本身规定的。

在我们这个项目里：

- 寄存器 2 = 0 → 水泵停止
- 寄存器 2 = 1 → 水泵运行

但这个约定**只存在于 PumpHMI 的代码里**。模拟器不知道 0 和 1 的含义，它只是个存数字的盒子。换一个项目，寄存器 2 完全可以表示别的东西。

**教训**：Modbus 是**搬数字的**，不是**懂数字的**。语义必须靠上位机和下位机约定，写在文档里。

### 💬 "为什么变成零了之后，还是会检测到压力"

这是我整个开发过程里**最久才想通**的一个问题。

我点了"停止水泵"，模拟器里寄存器 2 变成了 0。**但寄存器 0（压力）的值还在那里**，所以图表继续画线。我的直觉是"泵停了，压力应该归零啊？"

真相是：**Modbus Slave 模拟器只是一块白板**。三个寄存器只是三个独立的格子，**它们之间没有任何关系**。模拟器不知道"水泵"是什么，更不会模拟"泵停了所以压力降"的物理过程。

PumpHMI 也只负责**抄写**：白板上写什么我就显示什么。

真实世界里，"泵停 → 压力降"这个**物理过程**是由真实设备完成的：水泵停转 → 管道压力自然下降 → 压力传感器读到新值 → PLC 把新值写回寄存器 0 → HMI 才能读到新的压力。模拟器没有水泵、没有管道，所以这个过程不会发生。

**教训**：调试工具是工具，**别把工具当成真实设备**。要看到真实联动效果，得自己写一个会"思考"的模拟器（见第 10 章的 pymodbus 智能 mock）。

### 💬 "为什么停止水泵之后还在检测压力"

这是上一个问题的延伸。直觉是"停泵就该停止读数据吧"，但我最初的设计是**只要连上就一直轮询**。

后来想明白了：真实工业 HMI **就应该一直读**，因为：

- 设备本地可能被人手动操作，HMI 不读就不知道
- 出故障的瞬间最值得记录
- HMI = 操作员的"眼睛"，眼睛不能闭

但对 demo 场景，"停泵后界面安静下来"视觉上更直观。最终我做了个**违反工业最佳实践但更适合演示**的选择：让按钮同时充当监测开关，停泵就清零界面 + 停止轮询。

**教训**：**对的设计 vs 顺手的设计**有时候不一样。做学习项目时可以选后者，做产品时必须选前者，但你要知道自己选了什么。

### 💬 "Debug 切换到 Release 怎么切换"

这种问题不丢人。Qt Creator 的 Kit 选择器藏在**左下角竖排按钮**里，第一次找真的会找半天。

| 入口     | 怎么操作                                                |
| -------- | ------------------------------------------------------- |
| 快速切换 | 左下角 Kit 名 → 弹出面板 → Build 那栏选 Release         |
| 详细配置 | 左侧 Projects（扳手图标）→ Build & Run → 顶部 Edit 下拉 |

**教训**：IDE 的"显然在这里"和新手的"我怎么找不到"之间有巨大的鸿沟。**写教程时永远别假设读者知道按钮在哪**。

### 💬 "windeployqt 加 PATH 是干什么用的"

这个问题让我意识到 **PATH 环境变量** 对新手是个黑盒。

简单说：**PATH 告诉 Windows 在哪些目录里去找命令**。把 `D:\App\Qt6.11\6.11.1\mingw_64\bin\` 加进 PATH，就能直接敲 `windeployqt` 而不用打全路径。

但坑在哪？—— 如果电脑上还装了 **MSYS2**，它的 `windeployqt` 已经在 PATH 里了，**版本和 Qt 官方的不一致**。混着用会得到诡异错误。

我的选择是：**不加 PATH，每次打全路径**。代价是命令长，好处是不会撞车。这种"宁可麻烦也别埋雷"的取舍，写工控代码也是同样的思路。

**教训**：环境变量是把双刃剑。**搞不清楚的时候，宁可显式调用，别依赖隐式查找**。

### 💬 "为什么按下停止水泵，按钮还是变成启动水泵"

这是我做完"按钮反向同步"逻辑后才碰到的问题。

最初版本里，`onReadReady()` 会每秒读寄存器 2，根据它**反向同步**按钮文字。设计意图是：如果别人在模拟器里手动改了寄存器 2，HMI 也能跟着变。

但这制造了一个副作用：我点"停止水泵" → 写入成功，按钮文字变"启动水泵" → 一秒后轮询读到模拟器寄存器 2（如果模拟器不接受写入或者别的原因）→ 又把按钮文字改回"停止水泵"。**视觉上像没反应**。

后来在第 9 章重构时，**直接去掉了反向同步**：按钮成为唯一的状态来源，配合"停泵就停轮询"的设计，矛盾消失。

**教训**：**双向同步是个陷阱**。两个数据源谁说了算、谁覆盖谁、什么时候同步，没想清楚就会打架。在不确定要不要双向同步时，**先做单向**，加更复杂的逻辑前先证明它必要。

### 💬 总结：新手问题不丢人

写这一章不是自嘲，而是想说明一件事：**这些问题没有一个写在 Qt 官方文档里**。

文档告诉你 `QModbusTcpClient::connectDevice()` 怎么用，但不会告诉你"连不上要给用户什么反馈"。
文档告诉你 `QChart::addSeries()` 怎么用，但不会告诉你"实时数据必须关动画"。
文档告诉你 `windeployqt` 的参数，但不会告诉你"PATH 撞车了会怎样"。

**这些都是踩出来的**。如果你也是新手，遇到反直觉的现象时不要急着怀疑代码 —— 先怀疑自己**对工具的理解**，**对协议的理解**，**对系统行为的理解**。这些才是 99% 的卡点所在。

## 第 13 章 · 复盘 + 下一步

### 13.1 这套架构能直接接真实 PLC 吗？

**能，但要改三处**：

1. **IP 地址和端口**：`127.0.0.1:502` 改成 PLC 的局域网 IP
2. **寄存器映射**：要看 PLC 手册，可能不是 Holding Register 而是 Input Register；地址也未必从 0 开始
3. **Slave ID**：要看 PLC 设的 Modbus 单元号

业务逻辑、报警、图表代码**一行不用改**。这是 Modbus 协议的好处 —— **协议层抽象掉了"设备到底是谁"**。

### 13.2 这个项目没做的事

诚实地列一下，避免误导读者：

- **多设备 / 多寄存器分组**：真实工厂一台 PLC 可能挂几十个量，需要分组管理、按需查看
- **历史趋势**：数据库只存了报警，没存所有压力数据。完整历史趋势需要单独存一张时间序列表
- **用户权限**：操作员能看、工程师能改阈值、管理员能审计 —— 真实 HMI 必备
- **断线重连**：现在断线只是停止读取，没有自动重连机制
- **配置文件**：IP、端口、阈值都硬编码了，理想情况应该用 `QSettings` 或 JSON 配置

每一个展开都是一篇博客的量。但**核心通信和显示框架已经搭好**，加这些都是在已有结构上扩展。
